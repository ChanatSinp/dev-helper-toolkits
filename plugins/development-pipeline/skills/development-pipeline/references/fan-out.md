# Fan-out

Read before dispatching when Workflow 3a or 3b sends you here. Part of the orchestrator rules in `SKILL.md`; step numbers and "Delivery rules" refer to it.

- **Checkpoint before the first wave.** Save `git diff HEAD` to `.claude/temp/pre-fanout.diff` yourself and copy each untracked changed file to `.claude/temp/pre-fanout/<path>` (`mkdir -p` + `cp`), so a bad fan-out can be undone without guessing what was there. Replace it at each new fan-out; it is a restore point, not a review baseline. Restore only on the user's go-ahead: propose the exact commands (reset the touched files, re-apply the diff, copy back the untracked files) and run them once confirmed.
- **One implementer per package.** Dispatch one implementer per package — plan-driven-implementer for `app`, cdk-implementer for `cdk` (a mixed run below the threshold may give one implementer of each kind all its packages of that Owner) — a wave's packages concurrently in a single batch, waves in dependency order (a package runs only once every package it depends on has finished); model per the `SKILL.md` table. Each implementer reads only its slice `.claude/temp/wp/<package>.md`, whose Context Pack carries the `[shared]` entries plus that package's own (file map, symbols, contracts, commands), and treats files outside its package as read-only; the full pack in `plan.md` is the fallback, and an implementer that opens it reports the lookup. If the planner left the Context Pack thin or the slices missing, send the plan back rather than fanning out. Every package gets the same fixed brief — a cacheable shared prefix, variable part last: `Package mode. Project root: <abs path>. Conventions: <file(s)>. Read your slice(s) .claude/temp/wp/<ID>.md only. <pointers not in the Context Pack, if any>. Package(s): <ID>[, <ID>…], in dependency order.` In a fix round the brief also names the round (`Fix round <N>`).
- **Every fan-out ends with a consolidation dispatch.** After the last wave, dispatch plan-driven-implementer once more in consolidation mode — no new code, only: the `CLAUDE.md` update, the full lint/build/test run into `.claude/temp/verify.log` (settling any "sibling in progress" failure), and the manual test steps. Its brief is its whole input: say "consolidation — documentation and verification only, no code changes", and carry every package's "documentation needed" note, the union of the package changed-file lists (each package implementer reports only its own files; consolidation then adds its own), and the full lint/build/test commands from the planner's handback. Downstream stages run after consolidation, not after the last package.
