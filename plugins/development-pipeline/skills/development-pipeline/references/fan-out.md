# Fan-out

Read before dispatching whenever `plan.md` meets the fan-out threshold (3+ packages, or 2+ tiered `complex`). Part of the orchestrator rules in `SKILL.md`; step numbers and "Delivery rules" refer to it.

- **One implementer per package.** Dispatch one plan-driven-implementer per package — a wave's packages concurrently in a single batch, waves in dependency order (a package runs only once every package it depends on has finished); `model: sonnet` for packages the table marks `routine`, `complex` ones inherit yours. Each implementer reads only its slice `.claude/temp/wp/<package>.md`, whose Context Pack carries the `[shared]` entries plus that package's own (file map, symbols, contracts, commands), and treats files outside its package as read-only; the full pack in `plan.md` is the fallback, and an implementer that opens it reports the lookup. If the planner left the Context Pack thin or the slices missing, send the plan back rather than fanning out. Every package gets the same fixed brief — a cacheable shared prefix, variable part last: `Package mode. Read your slice .claude/temp/wp/<ID>.md only. <pointers not in the Context Pack, if any>. Package: <ID>.` In a fix round the brief also names the round (`Fix round <N>`).
- **Every fan-out ends with a consolidation dispatch.** After the last wave, dispatch plan-driven-implementer once more in consolidation mode with `model: sonnet` — no new code, only: the root/subdirectory `CLAUDE.md` update (package implementers are forbidden from touching it, and hand you a "documentation needed" note instead), the full lint/build/test run (package implementers ran only a compile check) with its complete output written to `.claude/temp/verify.log`, and the manual test steps for the whole change. Its brief is its whole input — it does not read `plan.md`: say "consolidation — documentation and verification only, no code changes", and carry every package's "documentation needed" note, the unioned changed-file list, and the full lint/build/test commands from the planner's handback. Downstream stages run after consolidation, not after the last package.
- **Union the changed-file lists before anything downstream.** Each package implementer reports only its own files. Merge the package lists before the consolidation dispatch (the union goes in its brief), then add consolidation's own files before the API-spec staleness check (Workflow 4a) and any downstream brief.
