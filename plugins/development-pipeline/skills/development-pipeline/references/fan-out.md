# Fan-out

Read before dispatching whenever `plan.md` meets the fan-out threshold (3+ packages, or 2+ tiered `complex`), or mixes `app` and `cdk` packages (Workflow 3b). Part of the orchestrator rules in `SKILL.md`; step numbers and "Delivery rules" refer to it.

- **Checkpoint before the first wave.** Save `git diff HEAD` to `.claude/temp/pre-fanout.diff` yourself and copy each untracked changed file to `.claude/temp/pre-fanout/<path>` (`mkdir -p` + `cp`), so a bad fan-out can be undone without guessing what was there. Replace it at each new fan-out; it is a restore point, not a review baseline.
- **One implementer per package.** Dispatch one implementer per package — plan-driven-implementer for `app`, cdk-implementer for `cdk` (a mixed plan below the threshold may give one implementer of each kind all its packages of that Owner) — a wave's packages concurrently in a single batch, waves in dependency order (a package runs only once every package it depends on has finished); model per the `SKILL.md` table. Each implementer reads only its slice `.claude/temp/wp/<package>.md`, whose Context Pack carries the `[shared]` entries plus that package's own (file map, symbols, contracts, commands), and treats files outside its package as read-only; the full pack in `plan.md` is the fallback, and an implementer that opens it reports the lookup. If the planner left the Context Pack thin or the slices missing, send the plan back rather than fanning out. Every package gets the same fixed brief — a cacheable shared prefix, variable part last: `Package mode. Read your slice(s) .claude/temp/wp/<ID>.md only. <pointers not in the Context Pack, if any>. Package(s): <ID>[, <ID>…], in dependency order.` In a fix round the brief also names the round (`Fix round <N>`).
- **Every fan-out ends with a consolidation dispatch.** After the last wave, dispatch plan-driven-implementer once more in consolidation mode — no new code, only: the root/subdirectory `CLAUDE.md` update (package implementers are forbidden from touching it, and hand you a "documentation needed" note instead), the full lint/build/test run (package implementers ran only a compile check, which a sibling's unfinished edit can break: a package's "sibling in progress" failure is settled here, not retried) with its complete output written to `.claude/temp/verify.log`, and the manual test steps for the whole change. Its brief is its whole input — it does not read `plan.md`: say "consolidation — documentation and verification only, no code changes", and carry every package's "documentation needed" note, the unioned changed-file list, and the full lint/build/test commands from the planner's handback. Downstream stages run after consolidation, not after the last package.
- **Union the changed-file lists before anything downstream.** Each package implementer reports only its own files. Merge the package lists before the consolidation dispatch (the union goes in its brief), then add consolidation's own files before the API-spec staleness check (Workflow 4a) and any downstream brief.
