# Fan-out

Read before dispatching when Workflow 3a or 3b sends you here: a fan-out the user asked for, or a mixed `app`+`cdk` run. Without the user's request, a mixed run is sequential — one implementer per Owner takes all its packages in dependency order (one per stretch when the chain alternates owners), one dispatch at a time, never concurrent — and the wave rules below do not apply. Part of the orchestrator rules in `SKILL.md`; step numbers and "Delivery rules" refer to it.

- **Checkpoint before the first wave.** Save `git diff HEAD` to `.claude/temp/pre-fanout.diff` yourself and copy each untracked changed file to `.claude/temp/pre-fanout/<path>` (`mkdir -p` + `cp`), so a bad fan-out can be undone without guessing what was there. Replace it at each new fan-out; it is a restore point, not a review baseline. Restore only on the user's go-ahead: propose the exact commands (reset the touched files, re-apply the diff, copy back the untracked files, delete untracked files the fan-out created) and run them once confirmed.
- **One implementer per package.** In a requested fan-out, dispatch one implementer per package, routed by Owner (`SKILL.md` 3b), per wave — a wave's packages concurrently in a single batch, waves in dependency order (a package runs only once every package it depends on has finished); model per the `SKILL.md` table. Each implementer reads only its slice `.claude/temp/wp/<package>.md`, whose Context Pack carries the `[shared]` entries plus that package's own (file map, symbols, contracts, commands), and treats files outside its package as read-only; the full pack in `plan.md` is the fallback, and an implementer that opens it reports the lookup. If the planner left the Context Pack thin or the slices missing, send the plan back rather than fanning out. Every package gets the same fixed brief — a cacheable shared prefix, variable part last: `Package mode. Project root: <abs path>. Conventions: <file(s)>. Read your slice(s) .claude/temp/wp/<ID>.md only. <pointers not in the Context Pack, if any>. Package(s): <ID>[, <ID>…], in dependency order. Report every file you created or edited, by path.` In a fix round the brief also names the round (`Fix round <N>`).
- **Every fan-out or mixed run ends with a consolidation dispatch.** After the last wave or dispatch, dispatch plan-driven-implementer once more in consolidation mode — no new code, only: the `CLAUDE.md` update, the full lint/build/test run into `.claude/temp/verify.log` (settling any "sibling in progress" failure), and the manual test steps. Its brief is its whole input: say "consolidation — documentation and verification only, no code changes", and carry every package's "documentation needed" note, the union of the package changed-file lists (each package implementer reports only its own files; consolidation then adds its own), and the full lint/build/test commands from the planner's handback (add no per-package synth). Downstream stages run after consolidation, not after the last package.
